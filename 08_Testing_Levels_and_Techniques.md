# Testing Levels

Testing Levels define different stages at which software is tested during the Software Testing Life Cycle (STLC).

---

# Unit Testing

## Definition
Unit Testing is the testing of individual units or components of an application.

### Performed By
Developer

### Purpose
- Verify individual methods or functions
- Detect defects early

### Example
Testing the login() method separately.

---

# Integration Testing

## Definition
Integration Testing verifies whether multiple modules work correctly together.

### Performed By
Tester / Developer

### Example
Checking whether the Login module successfully connects with the Dashboard module.

---

# System Testing

## Definition
System Testing verifies the complete application in an environment similar to production.

### Performed By
QA Team

### Purpose
- Validate complete system functionality
- Ensure business requirements are met

### Example
Testing the entire E-commerce application from login to payment.

---

# User Acceptance Testing (UAT)

## Definition
User Acceptance Testing is performed by the client or end users to verify that the software meets business requirements.

### Performed By
Client / End User

### Purpose
- Confirm software is ready for release
- Ensure business needs are satisfied

### Example
The client tests the final application before approving deployment.

---

# Difference Between Testing Levels

| Testing Level | Performed By | Focus |
|---------------|-------------|-------|
| Unit Testing | Developer | Individual component |
| Integration Testing | Tester / Developer | Interaction between modules |
| System Testing | QA Team | Complete application |
| User Acceptance Testing (UAT) | Client / End User | Business requirements |
